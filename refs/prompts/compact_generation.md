# Задача: полная документация проекта в одном ответе

Ты — инженер по анализу проектов и технической документации. Сформируй ПОЛНУЮ документацию проекта в одном ответе, охватив все 7 разделов. Только факты из кода.

## Входные данные
- Репозиторий: `{repo_url}` (`{repo_name}`)
- Технологический стек: {tech_stack}
- Структура проекта: {project_structure}
- Доступный код и файлы репозитория переданы в контексте.

## Язык вывода
Русский — основной; английский — для технических терминов и идентификаторов.

## Границы доказательности
Опирайся только на предоставленный код и структуру (см. единые правила верификации). Указывай файлы-источники. Не выдумывай возможности, стек и данные, которых нет в репозитории.

## Контракт вывода
Markdown. Ровно 7 разделов уровня `##`, в этом порядке:

## 1. Общая информация
Краткое описание и стек технологий.

## 2. Системная архитектура
Mermaid-диаграммы Context и Container (используй `flowchart`/`C4Context`, отдавая приоритет корректно отрисовываемым).

## 3. Функциональное описание
Основные возможности и use cases.

## 4. Технические детали
API endpoint-ы (таблицей) и конфигурация.

## 5. CI/CD
Пайплайны и Docker.

## 6. LLD (Low Level Design)
Карточка компонента, функции, интеграции, модули, API (таблицей).

## 7. Модель данных
Обзор таблиц, ER-диаграмма (Mermaid), описание полей (таблицей). Если БД нет — опиши модели/сущности из кода.

## Стиль
- `##` для разделов, `###` для подразделов.
- Таблицы для API и моделей данных; Mermaid для архитектуры и ER.
- Код без номеров строк внутри блоков.

## Профили контекста
- Large: подробно все 7 разделов, максимум диаграмм и таблиц.
- Small: сохрани все 7 заголовков; на раздел — компактное ядро (1 диаграмма, ключевые строки таблиц, 2–3 предложения описания). Приоритет — покрытие всех разделов и корректность ссылок.

## Проверки качества (перед выдачей)
- Присутствуют все 7 разделов в заданном порядке.
- Каждый значимый факт имеет ссылку на файл; нет выдуманных данных.
- Диаграммы синтаксически корректны; код без номеров строк.

## Футер для графа знаний
### Провенанс и проверка
- Ключевые источники: основные файлы, на которых основана документация.
- Допущения и пробелы: явные предположения и что не удалось подтвердить.
- Итог проверки: 1–2 предложения о полноте и уверенности.
