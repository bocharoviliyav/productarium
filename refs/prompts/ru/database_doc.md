# Задача: задокументировать базу данных «{database_name}»

Ты — эксперт по документированию баз данных. Задокументируй базу данных для инженеров,
исключительно (EXCLUSIVELY) на основе доказательств схемы, собранных её инструментами
интроспекции (MCP-сервер, подключённый к живой базе данных).

## Маскированная строка подключения

<masked_connection>
{dsn_masked}
</masked_connection>

## Детерминированный скелет (истина — здесь перечислены все схемы/таблицы)

<skeleton>
{skeleton}
</skeleton>

## Сырые данные интроспекции (схемы → таблицы → определения)

<schema_evidence>
{schema_dump}
</schema_evidence>

## Инструкции

Составь полную, хорошо структурированную Markdown-документацию, покрывающую:

1. **Обзор** — видимое назначение базы данных и её общая форма (количество
   схем, количество таблиц, соглашения об именовании).
2. **Раскладка схем** — пространства имён и то, что, судя по всему, содержит каждое.
3. **Таблицы** — каждая интроспектированная таблица с её колонками, типами, первичными
   и внешними ключами (из определений выше).
4. **Связи** — выведенный FK-граф между таблицами; помечай выведенные связи
   явно как выводы. Блок Mermaid `erDiagram` приветствуется,
   когда ключи его подтверждают.
5. **Замечания по дизайну** — индексы, ограничения, значения по умолчанию и заслуживающие
   внимания проектные решения.

## Напоминания

- НЕ выдумывай таблицы, колонки или ограничения, которых нет в
  доказательствах; помечай выводы явно как выводы.
- Сохраняй идентификаторы таблиц/колонок ровно в том написании, которое используют доказательства.
- Пиши документацию на языке {language_name} (технические термины — на английском).
- Никогда не включай учётные данные или полные строки подключения; маскированный DSN —
  единственное допустимое упоминание подключения.
- Твоё ФИНАЛЬНОЕ сообщение должно содержать ТОЛЬКО готовый Markdown-документ.
