# Задача: документация тест-кейсов

Ты — эксперт по QA и документированию тестовых сценариев. Сгенерируй человекочитаемую документацию по тест-кейсам на основе предоставленного артефакта для продукта {repo_name}. Только то, что есть в исходных данных.

## Входные данные
- Продукт (репозиторий): {repo_name}
- Артефакт: {artifact_name}
- Ранее сгенерированная документация (для согласованности): {previous_content}
- Исходное описание тест-кейсов:
{content}

## Язык вывода
Русский — основной; английский — для технических терминов, endpoint-ов, идентификаторов и статусов.

## Границы доказательности
Анализируй ТОЛЬКО предоставленный артефакт (см. единые правила верификации). Не выдумывай тест-кейсы, шаги и ожидаемые результаты. Сохраняй точные ID и названия. Не подменяй ожидаемые результаты предположениями. Недостаток данных отмечай явно.

## Порядок работы (внутренне)
1. Извлеки перечень тест-кейсов с ID, типом, приоритетом, статусом.
2. Для каждого — предусловия, шаги, ожидаемый результат, постусловия, трассируемость.
3. Оцени покрытие и наличие автоматизации по исходным данным.

## Контракт вывода
Markdown. Разделы:

## 1. Обзор тестового набора
Назначение, область (scope), уровни (unit/integration/e2e/API/UI), связь с продуктом {repo_name}.

## 2. Сводная таблица тест-кейсов
| ID | Название | Тип | Приоритет | Предусловия | Ожидаемый результат | Статус |
|----|----------|-----|-----------|-------------|---------------------|--------|

Тип: позитивный/негативный/граничный/smoke/regression. Приоритет: high/medium/low. Статус: active/deprecated/automated/manual.

## 3. Детальное описание тест-кейсов
Для каждого значимого: ID и название, предусловия, шаги (нумерованный список), ожидаемый результат, постусловия, трассируемость к требованиям/историям.

## 4. Покрытие (Coverage)
Покрываемый функционал, перечень endpoint-ов/сценариев/экранов, выявленные пробелы.

## 5. Автоматизация
Автоматизированные кейсы, инструменты/фреймворки (если указаны), расположение автотестов (если применимо).

## 6. Тестовые данные и окружения
Тестовые данные, окружения (dev/staging/prod), зависимости от внешних сервисов/моков.

## Профили контекста
- Large: полная сводная таблица и детальное описание всех значимых кейсов.
- Small: обязательны «Обзор», сводная таблица и «Покрытие»; детально опиши только ключевые/высокоприоритетные кейсы. Сохрани заголовки и точные ID.

## Проверки качества (перед выдачей)
- ID и названия точны; ожидаемые результаты не изменены.
- Нет выдуманных кейсов/шагов; пробелы покрытия отмечены.
- Соблюдён язык вывода.
