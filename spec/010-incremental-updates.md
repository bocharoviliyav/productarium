# SPEC-010: Инкрементальные обновления документации

Статус: planned · Волна 4 (первый в волне) · Приоритет: высокий

Решения grilling: детект изменений — git diff (codebase) / диф каталог-фингерпринтов (database) / hash (spec); impacted-страницы через provenance + LLM-донастройка; dirty-флаги скрытые, пользователям не видны.

## Решение

1. **Скрытое состояние источника**: на артефакте JSONB `source_state` (`{kind, baseline, checked_at}`): codebase → commit SHA; database → hash каталог-фингерпринтов; spec → hash контента. Поле серверное, из клиентских ответов вырезается (по образцу verify-флагов `product_repo`).
2. **Детект изменений** (джоба «проверить изменения»):
   - codebase: в существующем managed-клоне `git fetch` + `git diff --name-only <baseline>..HEAD` (без реклона; бюджеты/таймауты стандартные);
   - database: повторная интроспекция каталог-пака (интроспекция-кэш v6) и сравнение fingerprint'ов объектов (механизм уже используется в `_run_deep_units`);
   - spec: сравнение hash контента.
3. **Impact-план**: изменённые файлы/объекты → страницы через сохранённый provenance (у codebase-страниц — список прочитанных файлов; у database — маппинг объект→страница) → один LLM-вызов «расширить множество затронутых страниц» по дереву страниц и списку изменений (консервативно: только добавить, с обоснованием; бюджет-кап). Результат — список `impacted_page_ids` + сводка изменений для UI.
4. **Инкрементальная регенерация**: существующий механизм `force_pages` (`api/routers/docgen.py`): прогон только impacted-страниц, merge по образцу database-force_pages; версии — `append_version` как при обычной generate; память: переиндексация только изменённых страниц (upsert чанков уже гранулярный по source_id — довести до page-гранулы).
5. **UI**: на артефакте кнопка «Проверить изменения» → сводка (что изменилось, какие страницы затронуты) → «Обновить только изменённое» (с подтверждением); полная регенерация остаётся отдельной кнопкой. Dirty-признаки в UI не показываются.
6. **Интеграция**: SPEC-009 шедулер запускает «детект → инкремент» вместо полной генерации, когда baseline существует.

## Не-цели

- Merge текста страниц (старый/новый), ручное редактирование dirty-флагов, diff для HLD (HLD пересобирается из артефактов их же регенерацией).

## Критерии приёмки

- Герметичный сценарий «1 фича в фикстуре-репо» → перегенерированы только зависимые страницы (по provenance), версии/чанки остальных не тронуты.
- Database: добавление таблицы в мок-каталог → в план попадают только новая страница + зависимые (FK/зависимости).
- Спека: изменение контента спеки → полный реген её единственной страницы.
- Версионирование и memory-consistency: `current_version` корректен, поиск по памяти не содержит дублей.
