# SPEC-020: Маппинг доступа — выпадашки с поиском + перенос на страницу «Пользователи»

Статус: planned · Волна 12 · Приоритет: высокий

## Проблема

1. Фильтры матрицы grants в `MappingSection` (src/app/admin/page.tsx ~3803-3815) — обычные текстовые Input, а не выпадашки; пользователь ожидает дропдауны с поиском по вводу, одинаковые для локальных и внешних пользователей (все уже приходят из `GET /api/admin/users` с полем provider). (Пустыми они были из-за 404 — фиксы SPEC-019, здесь только UI.)
2. Отдельная секция «mapping» в навигации админки (Section-тип ~77, SECTIONS ~91, рендер ~4033) лишняя — маппинг должен жить на странице «Пользователи».

## Решение

- Новый минимальный `Combobox` в `src/components/ui.tsx`: controlled Input + фильтруемый по вводу список опций (клик/Enter — выбрать, Esc/blur — закрыть), опциональная «пустая» опция («все»). Без зависимостей, ~60 строк, стиль FIELD_BASE.
- В `MappingSection`: выбор продукта и пользователя — два Combobox с поиском по вводу (products из `/api/products`, users из `/api/admin/users` — единый список локальных и внешних); выбранный продукт фильтрует строки матрицы, выбранный пользователь — столбцы; «все» — ограничение снято. Текстовые Input-фильтры удалить.
- Перенос: убрать секцию `mapping` из Section-типа, SECTIONS и рендера AdminShell; `<MappingSection />` встроить в `UsersSection` ниже таблицы пользователей (целиком: матрица grants + карточка KC groups→roles). i18n-ключ `admin.sections.mapping` удалить (ru/en), интро маппинга оставить.
- KC groups→roles редактор не менять (только переезжает).

## Критерии приёмки

- В навигации админки нет пункта «Маппинг»; на «Пользователях» ниже таблицы — матрица grants и KC-маппинг.
- Выбор продукта/пользователя через Combobox (с поиском по вводу) фильтрует матрицу; одинаково для local и keycloak-пользователей.
- `bun run lint` / `bun run build` зелёные.

## Затрагиваемые файлы

`src/app/admin/page.tsx` (MappingSection, UsersSection, AdminShell, Section-тип), `src/components/ui.tsx` (Combobox), `src/…/ru.json`+`en.json`.
