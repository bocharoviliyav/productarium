# SPEC-011: Независимый скролл дерева навигации в артефакт-вьюере

Статус: planned · Волна 7 · Приоритет: средний

## Проблема

Дерево страниц в `src/app/products/[productId]/artifacts/[artifactId]/page.tsx` (~1073, `<aside className="lg:sticky lg:top-20 lg:self-start">`) прилеплено к вьюпорту, но не имеет собственного скролла. У длинных деревьев (database RE: сотни таблиц) низ дерева достигается только скроллом всей страницы — контент-колонка «уезжает», навигация теряется.

## Решение

- Контейнеру дерева (aside или внутреннему списку) задать `max-h-[calc(100vh-<выбранный отступ)]` + `overflow-y-auto` с тонким скроллбаром, сохранив `lg:sticky lg:top-20 lg:self-start`; скролл дерева не должен скроллить страницу и наоборот.
- Мобильная раскладка (дерево в потоке над контентом) не ломается — ограничение только на `lg+`.
- Проверить `src/components/SpecEditor.tsx`: если там аналогичное дерево — тот же фикс.

## Критерии приёмки

- Дерево из 100+ пунктов скроллится внутри своей колонки на десктопе; контент-колонка при этом неподвижна.
- `bun run lint` / `bun run build` зелёные; визуальная проверка на длинном артефакте.

## Затрагиваемые файлы

`src/app/products/[productId]/artifacts/[artifactId]/page.tsx`, возможно `src/components/SpecEditor.tsx`.
