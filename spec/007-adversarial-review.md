# SPEC-007: Придирчивое ревью кодовой базы (три прохода)

Статус: planned · Волна 6 (после завершения В1–В5) · Приоритет: высокий

## Формат

Три независимых прохода сабагентами (по AGENTS.md «Reflection and Iteration»), скоуп — весь репозиторий (`api/`, `src/`, `tests/`, конфиги). Каждый проход = findings-отчёт (severity: critical/high/medium/low, файл:строка, обоснование, предлагаемый фикс) + точечные диффы.

1. **Simple Review (минимализм/поддерживаемость/читабельность)**
   - минимальность кода: лишние абстракции/обёртки/хелперы, дублирование (DRY), мёртвый код, неиспользуемые импорты;
   - стиль: Google Python Style / PEP 8, типизация 3.11+; Next.js 15 App Router конвенции, strict TS, границы client/server.
2. **Adversarial QA (эффективность и корректность)**
   - edge cases: null/пустые входы, пустые списки, таймауты, 429, конкурентные записи в джобы/версии/гранты;
   - эффективность: N+1-запросы, лишние полные перезагрузки продуктов, стриминг больших тел, батчинг;
   - герметичность тестов: mock-лики, покрытие веток ошибок.
3. **Pentest/DevSecOps (безопасность)**
   - инварианты AGENTS.md: `.env` не читается; `open_read_nofollow` + realpath confinement на всех агентских чтениях; Fernet для секретов MCP/headers; маскирование DSN/токенов; RBAC на всех эндпоинтах; path traversal; SSRF в HTTP-интеграциях/MCP; command validation (`api/mcp/policy.py`); rate limits; CSRF/cookie-флаги.

## Порядок работ

1. Прогон трёх проходов (параллельно), сборка единого отчёта `spec/findings-wave6.md`.
2. Валидация владельцем (что фиксим / wont-fix с обоснованием).
3. Фиксы отдельными сабагентами по группам замечаний (по одному файлу/домену на агента во избежание конфликтов).
4. Финал: полный pytest + `bun run lint` + `bun run build`; обновление Knowledge Graph при структурных изменениях.

## Критерии приёмки

- Отчёт покрывает все три линзы; каждое замечание имеет статус fixed/wont-fix.
- Все тесты/линты зелёные после фиксов; критические security-находки закрыты в обязательном порядке.
