# SPEC-024: Редактирование продукта в модалке + настройки (расписание + пользователи) в модалке шестерёнки

Статус: planned · Волна 13 · Приоритет: высокий

## Проблема

1. Редактирование продукта (Название/Описание/владелец) — инлайн-форма в хедере страницы продукта (`src/app/products/[productId]/page.tsx` ~700-801, editOpen): несимметрично новому паттерну «кнопка + модалка» (расписание уже так).
2. `ProductUsersPanel` рендерится отдельной секцией в потоке (~1592, canManage) — должен жить в модалке настроек вместе с расписанием.
3. Видимость кнопок не соответствует модели SPEC-023: карандаш должен быть у owner+admin, шестерёнка настроек — у owner+manager+admin; user/viewer_global не видят ни одной.
4. Секция «MCP-серверы» (`McpServersPanel`, ~1627-1629 в Reveal) — отдельный блок в потоке страницы; по тому же паттерну уходит в модалку настроек.

## Решение

- `src/lib/api.ts` `productAccess()` — UI-зеркало новых прав: добавить `canEditProduct` (owner || admin) и `canConfigure` (owner || manager || admin); сравнить логику с `api/auth/deps.py` из SPEC-023.
- Карандаш (`canEditProduct`) открывает Modal с формой Название/Описание/Владелец (владелец-поле — только для canEditProduct): перенести существующий editOpen-код и PATCH-логику как есть, инлайн-форму из хедера убрать.
- Шестерёнка (`canConfigure`, сейчас `user?.role === "admin"`) открывает Modal xl «настройки продукта»: внутри `ProductSchedulesPanel` (embedded) + `ProductUsersPanel` (перенести из потока, секцию ~1592 удалить) + `McpServersPanel` (перенести из ~1627-1629). Порядок блоков: расписание, пользователи, MCP-серверы. Внутренние права панели MCP (manage на мутации) не меняются.
- Обе кнопки — в хедере продукта (рядом с h1, где сейчас карандаш ~786-795 + шестерёнка SPEC-021); user/viewer_global не видят ни карандаш, ни шестерёнку.
- i18n: переиспользовать существующие ключи (editProduct-ключи инлайн-формы, schedulesTitle, users-панели); при нехватке — новые ключи в ru/en (владелец файла — этот агент).

## Критерии приёмки

- Карандаш виден только owner/admin, шестерёнка — owner/manager/admin; в модалке шестерёнки расписание + пользователи + MCP-серверы; инлайн-форма и секции пользователей/MCP исчезли из потока страницы.
- `bun run lint` / `bun run build` зелёные.
