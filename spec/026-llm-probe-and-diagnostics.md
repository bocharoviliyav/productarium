# SPEC-026: Честная проба LLM + диагностика ошибок генерации

Статус: planned · Волна 14 · Приоритет: высокий

## Проблема

1. Проба модели в админке (`api/routers/admin.py` `_ping_model_endpoint` ~959-1049) считает подключение успешным по GET /v1/models (200 + список моделей), а падение chat-пробы POST /v1/chat/completions со статусом 400 лишь дописывает в `chat_note` «(chat probe returned status 400)». Пользователь видит «Подключение успешно / OpenAI-compatible API reachable; 8 model(s)», хотя реальная генерация тем же запросом падает — 400 не трактуется как провал (401/403 обрабатываются отдельно).
2. Ошибки генерации обезличены: `generate_product_summary` (`api/docgen/summary.py` ~134-216) глотает любое исключение LLM (logger.warning + возврат ""), knowledge.py отдаёт 503 «no content available or the LLM is unreachable»; docgen-джоба при падении всех юнитов пишет «LLM недоступен или превысил таймаут». Реальная причина (класс исключения / ответ сервера) остаётся только в логах сервера.

## Решение

- Честная проба: chat-проба с 4xx/5xx → `success: False`; message включает имя пробуемой модели и sanitized-деталь ошибки сервера (первый ~200 символов `error.message`/`message` из JSON-тела ответа; для не-JSON — статус).
- При ровно 400 на chat-пробе — один fallback-повтор с `max_completion_tokens` вместо `max_tokens` (гейтвеи нового OpenAI-поколения); успех повтора — `success: True` + пометка в chat_note, что сработал fallback.
- Если пробуемая модель отсутствует в списке GET /v1/models — предупреждение в chat_note («model not listed by /v1/models»).
- `generate_product_summary`: при исключении LLM больше не молчать — пробросить доменную ошибку (типизированный exception с классом исходного исключения + коротким sanitized-сообщением); `api/routers/knowledge.py` (~468-475) ловит её и включает причину в detail 503 (базовый текст сохранить, добавить «: <причина>»). Пустой контекст (нет сущностей) — прежний 503 без причины.
- Docgen-джобы: в сообщение о полном провале юнитов добавить sanitized первую LLM-причину (класс + ~200 символов) из агрегата ошибок юнитов — место формирования сообщения найти в `api/docgen/jobs.py` (или рендере статуса).
- Санитизация везде: без stack trace, без полного тела ответа, без заголовков/токенов.

## Критерии приёмки

- Проба с chat-400 → success=false + читаемая причина; chat-400 + fallback-успех → success=true + note.
- Модель вне списка /v1_models → предупреждение в chat_note.
- 503 саммари несёт реальную причину; провальная docgen-джоба — первую LLM-причину в error.
- Полный hermetic-сьют зелёный; новые тесты: probe 400/fallback/не-в-списке, 503-детель саммари, агрегация ошибки джобы.

## Затрагиваемые файлы

`api/routers/admin.py`, `api/docgen/summary.py`, `api/routers/knowledge.py`, `api/docgen/jobs.py`, тесты (`tests/unit/`).
