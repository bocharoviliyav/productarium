# SPEC-013: Удаление версии документации

Статус: planned · Волна 8 · Приоритет: высокий

## Проблема

REST-эндпоинта удаления версии не существует вовсе (`api/routers/doc_versions.py` — только list/get/restore), но UI показывает корзину (вьюер, строки ~915–925) рядом с селектором версий. Пользователь ожидает «удалить версию», а `remove()` шлёт DELETE артефакта целиком — вместе со всей документацией, чанками памяти и историей. Симптом: «удаление версии удаляет всю кодовую базу, даже при другой активной версии».

## Решение

- REST: `DELETE /{product_id}/{segment}/{entity_id}/versions/{version}` (permission `manage`):
  - 404 — версии нет;
  - 409 — версия является текущей (`current_version`);
  - 409 — это единственная версия (базлайн нельзя остаться без истории; для удаления артефакта есть DELETE артефакта);
  - 409 — на неё ссылается `base_version` другой версии (SPEC-012).
- Удаляется ТОЛЬКО строка снапшота: артефакт, `generated_docs`, pages, чанки памяти, `current_version` не трогаются.
- UI:
  - убрать корзину артефакта из панели версий (источник ложного ожидания) — удаление артефакта остаётся в его явном danger-контексте (заголовок артефакта с подтверждением);
  - per-version delete в панели версий (иконка у не-current версий) с подтверждением.
- Ответ: `204 No Content`.

## Критерии приёмки

- Unit/интеграционные тесты: удаление старой версии не меняет артефакт и чанки; текущая/единственная/base-версия → 409; RBAC: docs → 403, manage → 204.
- UI: корзина артефакта исчезла из панели версий; per-version delete работает на не-current версиях; `bun run lint && bun run build` зелёные.
