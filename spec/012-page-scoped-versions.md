# SPEC-012: Дельта-версии для page-scoped изменений документации

Статус: planned · Волна 8 · Приоритет: высокий

## Проблема

Любое page-scoped изменение — регенерация одной страницы (`force_pages`), инкремент (SPEC-010), правка страницы — завершается `doc_version_repo.append_version` (`api/docgen/jobs.py:697`) с ПОЛНЫМ снапшотом всех страниц. На больших документациях (сотни страниц) каждая правка одной страницы дублирует весь документ в БД и раздувает историю. SPEC-010 закрыл случай «ничего не изменилось → нет версии», но изменившаяся страница всё равно кладёт полную копию.

## Решение

Copy-on-write дельта-версии:

- `DocVersionORM`: колонка `base_version` (int, nullable). Дельта-версия хранит только изменённые страницы (`pages` = override-подмножество), `generated_docs = None`; полные версии (полный generate) остаются как сейчас (`base_version = None`, полный `pages`).
- Источники дельт: `edit` (page-edit), `generate` с `force_pages` (page/branch regen), `incremental`, `restore` (rollback тоже может быть дельтой: base = восстанавливаемая версия, overrides = страницы, отличающиеся от текущей).
- Материализация при чтении/restore: `get_version`/`restore_version` собирают полный вид — рекурсивно base + overrides; лёгкий режим материализует только метаданные + запрошенную страницу.
- Запрет цепочек глубиной > N (напр. 50): при превышении дельта «разглаживается» в полный снапшот.
- Лист версий помечает дельты (`scope: full|page`), UI — бейджем; никаких изменений в UX помимо бейджа.
- Обратная совместимость: существующие строки без `base_version` — полные версии, читаются как раньше.

## Критерии приёмки

- Регенерация 1 страницы документа на 200 страниц не копирует 199 неизменённых страниц (unit-тест на содержимое снапшота).
- Просмотр/restore дельты возвращает полный корректный документ (материализация, тест с цепочкой base→delta→delta).
- Цепочка >50 дельт разглаживается; все существующие тесты версий зелёные.
